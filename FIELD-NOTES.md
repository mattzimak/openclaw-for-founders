### Browser choice

- My pick: Brave Search.
- Three reasons:
- You already have the filters you need. Brave's API returns structured results with country/language/time filters built in - which matters for Agentmatik's Central European SME work where you'll want to scope queries to CZ/DE/AT/PL locales and recent dates.
- Generous free tier, clean billing. 2,000 queries/month free, then pay-per-query with no subscription floor. Exa, Tavily, and Perplexity are all more expensive per call and Perplexity especially gets pricey fast if your agent is chatty.
- Independent index. Brave crawls its own web, so it's not gated behind Google/Bing rate limits or ToS. That matters when you're running this on a Mac Mini that might sit idle for a week then burst-query during a standup pipeline run.
- The tradeoffs to know:
- Exa Search is better if your agent will mostly do semantic/research queries ("find papers similar to this one"). For chat-agent "what's the latest on X" stuff, Brave is better.
- Gemini (Google Search) grounds through Google's index, which has the best recency for breaking news - but it ties this tool to Google billing, adds another credential to manage, and you already have Gemini configured elsewhere in your stack via Vertex plans.
- Tavily is LLM-optimized (returns summaries, not raw SERPs) and is what a lot of the agentic-AI tutorials default to - but it's the priciest of the bunch and the summarization layer can flatten nuance you'd want Claude to judge itself.
- SearXNG is the key-free option if you want to self-host a meta-search aggregator. Good long-term for cost control, but more infra to run - skip for now, add later if Brave costs get out of hand.

### Skill package manager

- BUN - all three work, but they're not equal on a Mac Mini running OpenClaw as a persistent agent host:
- bun - fastest installer by a wide margin (native Zig, parallel fetching), smallest disk footprint, runs the skills directly without a separate Node resolution pass. For a machine that'll be installing skills occasionally and then running them often, bun is the clear winner. The only real downside is it's the newest of the three and occasionally a package with weird postinstall scripts misbehaves - but the skills listed here (1password, clawhub, gemini, github, gog, model-usage, nano-pdf, openai-whisper, sag, wacli, xurl) are all well-behaved TypeScript/JS packages that work fine on bun.
- pnpm - good middle ground. Content-addressed store means if you later add more OpenClaw instances (you mentioned wanting OpenClaw on both your main machine and the Mac Mini), shared packages deduplicate across them. Slower than bun on cold installs, faster than npm. Solid conservative pick.
- npm - safest in the "nothing weird will happen" sense, but slowest and the most disk-hungry. Zero reason to pick it unless you're debugging a specific skill install failure that turns out to be a bun/pnpm quirk.
- Can switch anytime
  ```bash
  openclaw skills reinstall --package-manager pnpm
  ```

### Hooks choice

- boot-md - Runs BOOT.md in your workspace on every gateway start, injecting persistent operational context (who your agent is, what you're working on) so the agent wakes up in-character.
- bootstrap-extra-files - Auto-creates/copies reference files into the workspace on startup, useful for ephemeral environments (containers, fresh VMs) where the workspace isn't durable.
- command-logger - Logs every shell/tool command the agent runs with args and exit codes, giving you an audit trail of exactly what your agent did and when.
- session-memory - Persists in-progress conversation threads across gateway restarts so your agent doesn't forget the current thread every time the Mac Mini reboots.

### Control UI

- The URL (127.0.0.1:18789) - stable. The port (18789) is chosen once during onboarding and sticks across restarts. Regenerable with openclaw dashboard or openclaw status anytime. No need to save - just bookmark in your browser for convenience.
- The Token - This is the sensitive bit. It's the auth token that lets anyone on 127.0.0.1 access the Control UI without logging in. Treat it like a password. A few things to know:
  - It's already saved - OpenClaw wrote it to ~/.openclaw/openclaw.json (or ~/.openclaw/auth/). You can always regenerate the full URL with openclaw dashboard --with-token, so you never strictly need to copy it elsewhere.
  - It's scoped to 127.0.0.1, so someone would need to be on the Mac Mini (or SSH'd in) to use it. Not a public-internet secret.
  - But - if you use the SSH tunnel pattern from your main machine to reach the dashboard, the token rides over that tunnel. Keep it out of Slack pastes, screenshots you share outside this chat, and git commits.

### First week

- day 1-2: set up SOUL.md, have normal conversations, ask it stupid questions, get comfortable
- day 3-4: start using it for real tasks. calendar, reminders, web searches, summarizing articles. the boring stuff.
- day 5-7: refine your SOUL.md based on what annoyed you. check your costs. get a feel for your daily usage.

### After week 1

- if your agent feels useful, your costs are under $10, and nothing is randomly breaking, you're ready to start experimenting. add web search if you haven't. then a daily briefing skill. then maybe calendar integration if you want proactive reminders.
- Build slowly. Earn each new capability by making sure the last one is stable first.
- The people who survive month one are the ones who started boring. Trust the boring.
- That's it. no skills. no second agent. no multi-agent orchestrator. no cron jobs. just one agent that knows who you are and does basic tasks reliably.

### Make the agent learn from its mistakes

- By default, every session starts clean. Your agent has no memory of the last time it tried something and failed, or the last time you corrected it. Two weeks later, it is still repeating day-three mistakes.
- The minimum fix is a .learnings/ folder in your workspace with two files:
- .learnings/ERRORS.md - command failures, breakages, exceptions
- .learnings/LEARNINGS.md - corrections, knowledge gaps, workflow discoveries
- Add this to SOUL.md:
  ```text
  Before starting any task, check .learnings/ for relevant past errors.
  When you fail at something or I correct you, log it to .learnings/ immediately.
  ```
- Over time, repeated lessons can be promoted into SOUL.md itself so they apply automatically in future sessions.
  ```bash
  Implement a self-improving learnings system in my OpenClaw workspace.

  Do all of the following:

  1. Create a `.learnings/` folder if it does not exist.
  2. Create `.learnings/ERRORS.md` for failures, breakages, command errors, and exceptions.
  3. Create `.learnings/LEARNINGS.md` for corrections, workflow discoveries, preferences, and things the agent should remember.
  4. Update `SOUL.md` so it includes these rules:
  - Before starting any task, check `.learnings/` for relevant past errors.
  - When you fail at something or I correct you, log it to `.learnings/` immediately.
  5. If there is already an existing memory or lessons system, merge carefully instead of duplicating it.
  6. Add a short section explaining how future entries should be written so the files stay useful.

  Then show me:
  - what files you created or changed
  - the exact rules you added
  - one example `ERRORS.md` entry
  - one example `LEARNINGS.md` entry
  ```

## Security

Links for this section are in [README.md](README.md#security).

- [Security (OpenClaw docs)](https://docs.openclaw.ai/gateway/security):
  - If you're on a VPS or any internet-connected machine:
    ```text
    openclaw config get | grep -E "host|bind"
    ```
  - If it says 0.0.0.0 Your agent is accessible to anyone who finds your IP. there are 500,000+ OpenCLAW instances exposed on the public internet right now. one had a zero-click exploit (CVE-2026-25253, patched) that let attackers hijack agents from a single webpage visit.
    ```text
    openclaw config set gateway.bind loopback
    ```
  - two minutes. do it before connecting any channel.
  - NeptrixAI - free tool that just adds that little bit more protection on top of everything
  - Never expose ports publicly - do not expose port 18789, SSH tunneling on local network as long as not exposing ports = ok to connect on local network) or Tailscale for private networking, Treat your gateway token like a password (built in deployment pipeline), even can SSH into VPS only from my network
  - VPS - Enable Docker sandboxing - architecture, Set sandbox.mode: "non-main" so group chats run in isolated containers.
  - OpenClaw page on security
  - Add approvals for destructive actions - draft-first for sending email, ask-before-delete for files, etc.
  - Most secure data encryption for inter-agent comms and all sensitive data, encryption slowing down so be picky
  - Regularly update your OpenClaw to the latest, most secure version (openclaw update)
  - run security audits regularly (openclaw security audit)

### ClawRouter

- Key Features:
- 4 routing profiles: auto (74-100% savings), eco (95.9-100%), premium (best quality), free ($0)
- 4 model tiers: SIMPLE → gemini-flash ($0.60/M) | MEDIUM → grok-code-fast ($1.50/M) | COMPLEX → claude-sonnet ($15/M) | REASONING → o3 ($10/M)

## Field notes

### General

- update openclaw via openclaw update in terminal and then restart the gateway openclaw service restart
- workspace folder usually .openclaw/\[agent_name\]-workspace
- rules on how its allowed to communicate with outside world

### Don'ts

- This is the mistake experienced users make. OpenClaw updates 2-3 times a week. Some updates break things. if you auto-update overnight, you might wake up to a broken setup with no idea what changed.
- Either pin your version and update manually when you're ready, or at minimum read the changelog before letting updates through.

### Anatomy of the workspace files

- AGENTS.md - OpenClaw’s core set of instructions and memory
- SOUL.md - Your agent’s persona, tone of voice, and clear boundaries
- IDENTITY.md - Your agent’s name, vibe, and personal emoji
- TOOLS.md - Notes on tools and how your agent should use them
- USER.md - All about you, your OpenClaw’s human
- cheat sheet for openclaw anatomy
- > SOUL md: personality, behavior and boundaries IDENTITY md: agent's name and role USER md: who you are and your preferences AGENTS md: operating instructions and rules to follow TOOLS md: apps, websites, APIs, etc. MEMORY md: remembering decisions, lessons learned, etc. SKILLS md: how to do something HEARTBEAT md: instructions to periodically wake up and do something cron jobs: instructions to wake up at a specific scheduled time to do something
- reference these files when you want to make clean changes.
- examples:
- "update your tools to include agentmail" "update your agents file to always ping me before sending an email" "update your memory so you always remember to sign an email as my assistant and not as me" "add a heartbeat to check for email responses periodically throughout the day" "create a cron job to send me an email report at 9am sharp every day"
